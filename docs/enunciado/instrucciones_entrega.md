## Control de código y control de versiones (GitHub)

El desarrollo del proyecto se realizará de forma transparente y colaborativa a través de la plataforma GitHub. Es obligatorio que todo el flujo de trabajo quede registrado en la plataforma.

- **Creación del Repositorio:** Cada equipo creará un repositorio único en GitHub, con visibilidad pública (o privada, con acceso directo para los usuarios de GitHub del equipo docente). Este repositorio debe estar creado antes del 3 de noviembre de 2026.
- **Actualización Continua:** El código debe actualizarse de forma incremental a lo largo de la práctica. Se evaluará el historial de commits y branches de cada miembro del grupo. No se aceptarán entregas masivas realizadas el último día. Se valorará positivamente la definición de los work ítems, así como su resolución y cierre mediante commits.
- **Evolución de la Memoria Técnica:** En la raíz del repositorio debe mantenerse y actualizarse un archivo de documentación (Markdown/README o carpeta /docs) donde se documente la evolución del planteamiento del problema, las decisiones de diseño y los avances. El fichero README debe incluir la descripción del proyecto y de sus componentes, así como las instrucciones para reproducirlo.
- **Entorno de Ejecución (Requirements):** Es imprescindible incluir en la raíz del repositorio el archivo `requirements.txt` (o `environment.yml`) que detalle exactamente todas las librerías y sus versiones utilizadas para garantizar la reproducibilidad completa del proyecto. Recordar establecer las semillas necesarias. Es recomendable crear un entorno virtual para ejecutar el proyecto.

> **Requisito de trabajo colaborativo.** El profesorado auditará la aportación individual de cada alumno mediante el historial de commits y ramas de GitHub. Aseguraos de realizar commits descriptivos desde vuestra cuenta individual.

## 4. Detalle de los entregables

### 4.1. Memoria Técnica del Proyecto (Máx. 15 páginas)

Deberá maquetarse obligatoriamente utilizando la plantilla facilitada en la asignatura. No se evaluará ninguna memoria que supere las 15 páginas. Debe estructurarse en los siguientes apartados:

1. Introducción
2. Materiales: explicación del dataset y análisis exploratorio inicial. Junto con el preprocesamiento necesario sólo para la parte descriptiva.
3. Métodos: explicación de la metodología seguida para la construcción y selección de los modelos, incluyendo el preprocesamiento para la aplicación de machine learning.
4. Análisis de resultados: Análisis y justificación de las técnicas utilizadas.
5. Discusión y Conclusiones: análisis crítico, posibles mejoras y resultados más destacados.

### 4.2. Vídeo Explicativo del Proyecto (Máx. 7 minutos)

Presentación ejecutiva del proyecto grabada en formato audiovisual. Es un requisito estricto que:

- Participen obligatoriamente TODOS los miembros del grupo en la locución y/o en la exposición visual.
- Tenga una duración MÁXIMA de 7 minutos (los vídeos que excedan este tiempo sufrirán una penalización).
- Abordaje de forma sintética: la definición del problema, la solución arquitectónica implementada, una demostración/ejecución del código y las conclusiones principales.
- Se entregue mediante un enlace accesible (YouTube, OneDrive, Microsoft Stream o enlace directo de descarga).

### 4.3. Documento de Uso Ético y Responsable de Inteligencia Artificial

En consonancia con las directrices académicas del Máster, se permite el uso de herramientas de IA Generativa (ChatGPT, Claude, GitHub Copilot, etc.) como apoyo al desarrollo, siempre que se declare de forma transparente. Este documento debe incluir:

- **Registro de Prompts (Prompt Log):** Transcripción literal de las instrucciones/prompts principales utilizados durante el desarrollo del código y la redacción.
- **Herramientas Empleadas:** Especificación de los modelos, versiones y entornos de IA utilizados.
- **Análisis Crítico y Validación:** Evaluación justificada de las respuestas obtenidas: qué código o sugerencia fue aceptado, cuál fue rechazado por errores, alucinaciones o ineficiencias, y cómo fue corregido por el equipo.

> **Nota.** Cualquier falta de transparencia en la declaración del uso de Inteligencia Artificial Generativa o la falta de participación no justificada de algún miembro del grupo en el vídeo implicará la no superación de la práctica.
